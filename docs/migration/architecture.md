# Arduino architecture specification

Status: architecture baseline for implementation; hardware-dependent choices require the T00 spike. Scope is the existing Orion application on the Adafruit MacroPad RP2040. This is not a claim of a working or measured Arduino port.

## Compatibility boundary
Preserve six core inputs (note, chords, drum, matrix, note_walk, chord_walk); user processor and input modules are supported through `module.json` manifests and generated tables (docs/modules/README.md, decisions.md ADR-12; each input adds a scene bank, and the generator enforces the SCN1 and LittleFS bounds), all implemented processors, ten logical slots (SET, IN, six processors, OUT, SETTINGS), all musical tables, parameter names/defaults/ranges, pad order, shortcuts, screen content, LEDs, 24 PPQN transport, routing operations, and SCN1 persistence. See discovery reports and `behavior-contracts.md` for source evidence; source wins when notes disagree. The registry's phraser has no implementation and is hidden. No DIN MIDI, audio engine, or new modules are in scope. The user's requested MIDI/UI core split is included, subject to T00/T11a feasibility validation.

Intentional differences: no garbage collection or scene-switch interpreter restart; invalid persistent values are rejected safely; fixed memory exhaustion is diagnosed; late output is bounded; USB disconnect cannot hang the application. Arduino will use LittleFS and an explicit USB CDC maintenance import/export tool instead of exposing CIRCUITPY as a writable USB disk. Existing scene text remains importable. Preserve a held-key maintenance entry and document its new workflow. These differences must be visible in migration documentation and tests.

## Layers and ownership
`firmware/Orbit12/Orbit12.ino` initializes core-owned adapters: `setup/loop` call `EngineApp::poll()` on core 0 and `setup1/loop1` call `UiWorker::poll()` on core 1. Arduino-recursive sources live under `firmware/Orbit12/src/`:

| Area | Owns | Must not own |
|---|---|---|
| domain/types, time, note_buffer, music | bounded data, source musical tables, wrap arithmetic | hardware, files, UI |
| domain/transport | clock phase, swing, internal/external state, Start/Stop/Continue | USB writes, rendering |
| domain/output | ordered notes, held identities, release safety, outgoing clock | module processing |
| domain/modules | input and processor algorithms, parameters and saved state | display, GPIO, filesystem |
| domain/chain | slot routing, tap snapshots, source/operation/channel policy | module-specific algorithms |
| app/controller and ui_model | shortcuts, focus/edit state, scene actions, render model | direct hardware calls |
| persistence | SCN1 parser/writer, validation, lifecycle transaction | real-time processing |
| platform/macropad | GPIO, encoder, SPI OLED, NeoPixel, USB MIDI/CDC, LittleFS | musical rules |
| app/app | composition and cooperative scheduling | duplicate algorithms |

Use explicit constructor references. A small function-pointer module descriptor plus in-place tagged state replaces Python lazy imports. No module subclass hierarchy and no shared helper giving every module every service. Descriptors and static tables reside in flash. A compile-time union contains each module's state; six processor slots may all instantiate the largest processor. Input state has a separate union. Placement construction/destruction is allowed on slot changes; no heap. Compute size/alignment from the actual types, not a guessed byte arena. Assert trivial or explicitly handled lifetimes.

## Memory model
Retain base note capacity 12 and output/held capacity 24, as observed. Preserve module-local source capacities (including larger scheduler buffers) from the detailed runtime inventory; do not replace them all with a single arbitrary queue. Allocate per-slot tap snapshots explicitly, with lifetime through one chain pass. Buffers are caller-owned and no algorithm retains spans/references to another slot's scratch memory.

Initial system budgets: 64 input events (source capacity), 256 normalized USB receive events, 128 MIDI transmit packets, one 1024-byte framebuffer, one scene staging object, and streaming file I/O buffers. These USB budgets are new engineering choices, not Python parity requirements. Compile-time assertions must keep application-owned static objects <=128 KiB and total linked static RAM <=176 KiB; target instrumentation must demonstrate >=48 KiB free margin after library setup under worst chain/scene load. These are release gates, not measured results. If six largest module states exceed budget, Sol submits measured alternatives before reducing features/polyphony.

## Dual-core ownership and cooperative scheduling
Use both cores at the supported board default clock; record CPU and USB settings in the pinned profile. No arbitrary overclock or RTOS. Core 0 exclusively owns USB/TinyUSB/CDC, transport, chain, controller/focus/parameter state, scenes and filesystem. Core 1 exclusively owns GPIO scanning, encoder ISR/delta, SPI OLED and NeoPixel objects, formatting/layout and framebuffer. Core 0 publishes bounded value snapshots; core 1 never reads module pointers or mutable engine state. Peripheral initialization happens on its owning core with a nonblocking ready handshake because setup functions start concurrently. Select separate 8 KiB stacks through the core-supported setting and include both in the memory budget; verify high-water marks.

Core 0 `poll()` order: service USB; consume at most 64 ordered input records; classify UI-consumed versus musical keys and apply bounded actions; advance transport; process input and all six processors; enqueue output (off before on, then source-defined clock ordering); drain bounded MIDI TX; publish a dirty UI snapshot at most 30 Hz. UI commands change authoritative state here; formatting and drawing happen on core 1. Parameter/menu work must be bounded (no full scene serialization or module reconstruction while running). Read at most 200 incoming messages per transport pass and consume at most one external TimingClock per pass, as source does. Retain at most one internal musical tick per poll and deadline-based fractional accumulation; service overdue work on subsequent polls, never skip musical tick count silently.

Core 1 polls inputs before each bounded render chunk, preserving timestamp and order in a 64-record SPSC ring. Use bounded SPI chunks so ordinary rendering never prevents the 3 ms key scan cadence. Encoder changes can be coalesced only while adjacent and cannot move across key/switch edges. On input overflow, publish an independent atomic fault latch; core 0 stops/releases and waits for an authoritative physical all-keys-up resync before restart. Latest UI snapshots use a three-slot SPSC queue with producer/consumer ownership; full means skip publication and retry with newest state next frame, never overwrite a slot being read. No waiting for renderer acknowledgements in musical playback. See contracts for memory ordering and startup/maintenance handshakes.

T00/T11a must prove selected libraries can be initialized on their owning cores and synchronization compiles to bounded nonblocking operations. If this cannot be achieved, Sol reports evidence and alternatives; do not silently revert to single-core or move USB to core 1. Shared XIP/bus traffic can still cause jitter; isolation is a measured target, not a hard-real-time guarantee. Flash writes deliberately quiesce both workers and occur only stopped.

Represent transport time in unsigned 32-bit microseconds with a fractional accumulator for 24 PPQN; retain wrap-safe 32-bit milliseconds for existing module delays. All comparisons use signed modular differences with deadlines less than half-range ahead. Do not mechanically translate Python tick masks. The adapter supplies both times from one sample. Tests compare source behavior at millisecond resolution; precision improvements cannot change event order, swing grouping, or start phase.

Drain at most 32 TX packets per poll and never wait for USB host acceptance. Store unsent packets. Reserve release/control capacity by stopping acceptance of new note-ons with at least 24 TX slots left. Overflow, excessive backlog (more than 96 pending clock ticks), or inability to preserve a release triggers a bounded recovery state: stop generating notes, drain explicit offs for accepted held identities and Stop, clear schedulers, report diagnostic, then require user restart. Disconnect clears local running state and queues cleanup for reconnect, without blocking. Do not silently resume stale notes after reconnect. Validate this with injected backpressure; do not claim musical parity under unlimited overload.

UI is dirty-driven on core 1, with a target ceiling of 30 Hz and 60-second sleep. Preserve the 1.5-second launch image using a startup state while core 0 services USB. The old fixed 12 ms single-core display gate is not an Arduino requirement. Bound render chunks and measure SPI/PIO effects on core 0. Encoder quadrature may use a minimal core-1 edge ISR recording only state/delta; no MIDI, storage, allocation, or drawing inside ISRs. Use bounded core-local interrupt protection for delta transfer if atomic read-modify-write is not lock-free. Poll/debounce key inputs at the source 3 ms cadence and switch at 1 ms; verify mechanical detents/direction on hardware.

## Persistence and scene lifecycle
Use core LittleFS with a profile-selected partition (initial target 1 MiB, confirmed by T00). Keep scene names Scene01..Scene16 (named slots, storage.md), active pointer and key_brightness text semantics; no new binary-only format. Stream SCN1 parsing into a fixed scene DTO; validate before mutating live state. Preserve valid parameter and save_attrs values, legacy slot remapping, unknown-name tolerance, and valid version-1 files. Unknown modules fall back to Note/Empty with a diagnostic; unsupported future schema rejects without overwriting the original. Do not mirror unsafe malformed-value behavior.

Storage operations occur only in an explicit stopped maintenance/scene transition, with notes released and USB serviced. Scene switch: quiesce and release -> save current/copy target as requested -> parse and validate target -> reset/reconstruct fixed slots -> apply parameter callbacks in source order -> commit active pointer -> rebuild UI -> return stopped. File failure leaves a recoverable prior scene and active pointer; never report success on partial writes. Use temp file + close + verified rename and backup recovery; test the selected LittleFS rename/power-loss semantics before claiming atomicity. Only explicit save/switch writes flash, no periodic per-loop save.

CDC maintenance tool supports bounded, framed LIST/GET/PUT of the sixteen scene slots, the scene names file and user settings, with length and checksum, ACK only after verified commit; reject other paths and oversized payloads. It enters only while stopped and rejects edits during performance. No USB MSC or simultaneous host/device filesystem mounting. Export from CIRCUITPY before flashing and import with this tool; bootloader UF2 remains the firmware installation path.

## Build
Arduino CLI `sketch.yaml` profile pins Arduino-Pico, exact MacroPad FQBN/menu options and exact library versions after T00. Choose Adafruit TinyUSB + FortySevenEffects MIDI with thru disabled; SH110x/GFX (and transitive BusIO if required), NeoPixel, core LittleFS. Never mix the core's alternate MIDI API with the selected TinyUSB stack. Core-provided TinyUSB is not independently installed at a conflicting version. Host CMake builds domain code and fake ports as C++17. No PlatformIO dependency layer or custom framework is necessary.

See `contracts.md`, `plan.md`, `testing.md`, and `decisions.md` for implementation and escalation boundaries.
